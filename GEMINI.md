# Правила и спецификации проекта: Onter's inn Shorts Engine

## 0. Трехэтапный пайплайн создания роликов (3-Step Production Pipeline)

### Этап 1. Вводные, нарезка геймплея и разбор бага
1. **Вход от пользователя:** Ссылка на видео (YouTube / локальный файл), таймкоды и вопрос/описание бага.
2. **Действия агента:**
   - Скачивание видео strictly на **диск E:** (`assets/downloads/` или `output/<id>/temp/`). Использование диска C запрещено.
   - Нарезка нужного фрагмента геймплея (5–10 сек) для фонового лупа.
   - **Превью геймплея:** Генерация чернового **MP4 видеоклипа** для проверки пользователем.
   - **🔍 Обязательная проверка нарезки (Frame Sampling Check):** Автоматическое извлечение и визуальный анализ кадров на 0–2 сек, в середине и в конце клипа для исключения стыков с чужими роликами/играми из компиляций и корректировки таймкодов.
   - Формулировка сути бага простыми словами (KISS: 2–3 очевидных фактора — коллизия, NaN, тик физики, луч Raycast).
3. **Контрольная точка 1:** Ожидание подтверждения от пользователя: отрезок геймплея и физическая суть бага согласованы.

### Этап 2. Сценарий, раскадровка и подбор схем (2D / 3D) — СРАЗУ 3 ВАРИАНТА
1. **Действия агента:**
   - **Генерация 3 разных вариантов ролика (Variant 1, Variant 2, Variant 3):**
     - Для каждого выпуска готовить сразу **3 различных сценария** с разной подачей материала, юмором и структурами хуков.
     - Разрабатывать **разные 2D/3D схемы и карточки кода** для каждого варианта (например: 1 — физика/коллизии, 2 — мировые координаты/Screen Space, 3 — код/State Machine).
     - Все 3 варианта собираются в отдельные папки (`output/<id>/variant1/video.mp4`, `variant2/video.mp4`, `variant3/video.mp4`), при этом один из них копируется в корень (`output/<id>/video.mp4`).
   - **Dual-Voice Standard:** Svetlana (host: Hook, Question, Outro) + Dmitry (expert: Physics, Code, Fix)
   - **Full Top 2/3 Container (1000x1280 px at y=80):** All visual cards/code cards must be rendered inside a full dark container 1000x1280 px placed at y=80. No floating code cards on y=220.
   - **Clean Reaction Memes:** Memes must be textless or max 1-2 simple words (reaction GIF: shock, facepalm, open-mouth cat). No dense text memes.
   - Публикация артефакта с превью сценариев и карточек для всех 3 вариантов.
2. **Контрольная точка 2:** Пользователь отсматривает сценарии, схемы и мемы.

### Этап 3. Правки и сборка строго по команде
1. **Итерация правок:** Агент точечно вносит все правки и пожелания пользователя во все 3 варианта (или в указанный пользователем вариант), правит текст, заменяет мемы или схемы.
2. **ОБЯЗАТЕЛЬНОЕ подтверждение:** Агент **никогда не начинает сборку автоматически** (автоподтверждение среды `auto-approval hook` НЕ считается согласием). Ждать явного ручного «ОК» / «Собирай» в чате!
3. **Финальный продакшн и 4-этапная авто-валидация:**
   - Синтез Edge-TTS по смысловым блокам строго в 2 голоса (Светлана + Дмитрий) с проверкой наличия обоих голосов.
   - Скачивание уникальных мемов для темы выпуска с префиксом `ep<id>_...` без использования старых кэшированных файлов.
   - Сборка **всех 3 вариантов видео** в FFmpeg (NVIDIA NVENC) с точным позиционированием 16:9 геймплея на `y=200`–`y=774` px.
   - **🔍 Обязательный Smoke Test целостности и проигрываемости:** Выполнение `ffprobe -v error -i <video.mp4> -f null -` для каждого из 3 вариантов и итогового `.mp4`. Проверка контейнера на отсутствие `moov atom not found` и декодируемость всех фреймов. При любых сбоях — автоматический перерендер до 100% готовности.
   - Генерация `description.txt` и `metadata.json`.
   - Итоговый отчет со ссылками на готовые варианты `video.mp4`.


## 1. Формат и целевые платформы
- **Формат видео:** 9:16 Вертикальное (1080x1920 px, 30 FPS).
- **Платформы:** YouTube Shorts, TikTok, Instagram Reels.
- **Длительность:** 30–50 секунд (идеальный хронометраж для удержания).
- **Аппаратный рендер на GPU (NVIDIA NVENC):** Всегда использовать аппаратное ускорение видеокарты (`-c:v h264_nvenc -preset p4 -cq 20`). Софтверный рендер на CPU (`libx264`) отключен, чтобы не грузить процессор и рендерить ролики за секунды.

## 2. Структура вывода файлов (Output Organization)
Каждый ролик/эпизод сохраняется в отдельной изолированной папке `output/<episode_id>/`:
```
output/<id>/
├── video.mp4          # Только готовый итоговый видеофайл в корне
├── voice/             # Сгенерированные TTS аудиофайлы (voice.mp3)
├── subtitles/         # Файлы субтитров (.ass)
├── visuals/           # Сгенерированные 2D-схемы, карточки кода
├── frames/            # Скриншоты и превью-кадры
└── temp/              # Промежуточные видеофайлы
```
В корне папки `output/` не должно быть мусора.

## 3. Визуальный лейаут и правила расстановки (Strict Zero-Overlap Vertical Grid)
Экран 1080x1920 строго разделен на изолированные зоны с защитными полями:
1. **Зона геймплея (Верх, `y=200`–`y=774`, ширина 1020px):**
   - Геймплей центрирован на размытом фоне в сценах геймплея.
   - **Беспрерывный луп (No Freeze-Frames):** Короткие фрагменты (5–10 сек) циклически прокручиваются без пауз и стоп-кадров.
   - ⛔ **СТРОЖАЙШИЙ ЗАПРЕТ НА ИСПОЛЬЗОВАНИЕ `preview_gameplay.mp4` ДЛЯ ФИНАЛЬНОГО МОНТАЖА (Zero Preview Reuse / No Double Framing):** Категорически запрещено подставлять файл черновика `preview_gameplay.mp4` (который уже содержит вёрстку с размытым фоном) в качестве исходника для финальной сборки в FFmpeg. В сборку должен поступать ТОЛЬКО чистый исходный нарез геймплея (`gameplay_clip.mp4` / `epXX_raw.mp4`). Использование `preview_gameplay.mp4` приводит к уродливому «двойному вкладыванию» и немедленной браковке видео.
2. **Зона схем и объяснений (Нижний центр экрана, `y=780`–`y=1380`, макс. размер $1000 \times 600\text{ px}$):**
   - **Центральное нижнее позиционирование под геймплеем (`y=780`, `overlay=(W-w)/2:780`):** Схемы и карточки кода рендерятся строго в центрально-нижней зоне кадра под окном геймплея (`y=200`–`y=774`). Накладывать карточки поверх геймплейного видео кадра КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО.
   - **Строгий вертикальный флоу (Сверху вниз, НЕ слева направо):** Схемы никогда не делятся на 3 тесные горизонтальные колонки. Элементы располагаются вертикальным стеком:
     - *Шапка:* Заголовок темы (`32–36px` Bold) + номер этапа (`20–22px` Monospace).
     - *Шаг 1 (Верхний блок, во всю ширину $1000\text{px}$):* Исходное состояние/3D-мир, крупные иконки (50px+), параметры (`24–26px`).
     - *Переходный коннектор (Стрелка вниз $\Downarrow$):* Крупная стрелка вниз с формулой/расчетом (`24–26px`).
     - *Шаг 2 (Нижний блок, во всю ширину $1000\text{px}$):* Реакция движка/Screen Space/баг, визуальная зона экрана и плашка ошибки.
     - *Итог (Футер):* Вывод в 1 строку (`22–24px`).
   - **🗣️ СТРОЖАЙШИЙ ЗАПРЕТ НА АНГЛИЙСКИЙ ЯЗЫК В ОЗВУЧКЕ / TTS:** Категорически запрещено использовать английские слова и термины в текстах дикторской речи. Озвучка Edge-TTS сбивается и искажает слова. Все термины переводить или строго транслитерировать кириллицей (`Криэйшн Энджин`, `Диалог Менеджер`, `Дор Авто Клоуз Таймер`, `Он Триггер Экзит`, `Волт 81`).
   - **🚫 ЗАПРЕТ ИЗБЫТОЧНОГО УСЛОЖНЕНИЯ ТЕРМИНОЛОГИИ (Clean Plain Language / No Overcomplicated Tech Jargon):** Категорически запрещено перегружать реплики дикторов узкоспециализированным или заумным птичьим языком там, где мысль можно передать простыми понятными словами:
     - Вместо `сокет аттача` -> говорить `пустой объект`, `точка привязки` или `крепление`.
     - Вместо `хэнд проп` -> убирать англицизмы, говорить `крепление руки`.
     - Вместо `скелетная анимация` -> просто `анимация`.
     - Вместо `блендшейп` -> `анимация` перелистывания.
     - Вместо `в коде аттача` -> `в коде крепления`.
     - Вместо `по нормали взгляда непися` -> `к нормальному направлению` или `по взгляду персонажа`.
     - Текст должен быть естественным, живым и легко воспринимаемым широкой аудиторией в Shorts/Reels, сохраняя суть бага без искусственной наукообразности.
   - **Дизайн-система:** Строгий графитовый стиль (`background: #14161a` / `#1c1f26`), цветная полоса слева (`border-left: 8px solid <color>`), крупная читаемая мобильная типографика (`24–28px` для основного текста).
   - **🚫 ЖЕСТКИЙ ЗАПРЕТ НА СМАЙЛИКИ (No Emojis in Motion Design):** Категорически запрещено использовать какие-либо unicode-смайлики/эмодзи (🎬, 🏎️, 📊, ⚡, 💡, ⚠️, 🔒 и др.) на 2D-схемах, карточках кода, 3D-оверлеях и HUD. Допустимы только чистый текст, строгие векторные значки/стрелки и геометрические баджи.
   - **📏 Правило 5 предложений (Max 5 Text Items per Screen):** На одном экране 2D-схемы разрешено размещать **не более 5 текстовых надписей/предложений**. Если материала больше — ОБЯЗАТЕЛЬНО разделять объявление на **2 отдельные схемы/карточки**.
   - **💻 Правила оформления карточек кода (Code Card Specs):**
     - Темная тема редактора (`#1e1e1e` / `#0f172a`), закругленные углы, 3 кнопки управления окном (красная, желтая, зеленая) слева в шапке + вкладка файла.
     - Нумерация строк серым моноширинным шрифтом (`#4b5563`).
     - Подсветка синтаксиса: комментарии (`#6a9955`), ключевые слова (`#569cd6`).
     - Строки с багами: подложка `#3b1d1d`, маркер `#f87171` + комментарий `// BUG!`.
     - Строки с фиксом: подложка `#1b3b22`, маркер `#4ade80` + комментарий `// FIX`.
3. **Зона мемов (Центр-Низ, `y=860`–`y=1400`, макс. высота 540px):**
   - В первой половине ролика (0–8s и 8–13s), когда схемы еще не активны, свободную нижнюю половину экрана (`y=860`) необходимо активно заполнять интересными контекстными мемами сюжетного барабана (`door closes behind my face meme`, `talk behind closed door meme`, `cant hear meme`).
   - ⛔ **СТРОЖАЙШИЙ ЗАПРЕТ НА НАЛОЖЕНИЕ МЕМОВ ПОВЕРХ КАРТОЧЕК КОДА И СХЕМ (Zero Code Card Overlap):** Категорически запрещено накладывать любые мемы, гифки или оверлеи во время показа карточек кода и 2D-схем. Во время активных карточек экран кода должен оставаться на 100% чистым и читаемым. Мемы показываются ТОЛЬКО в сценах чистого геймплея (`hook` / `investigation`), когда карточки не отображаются.
   - **Запрет рамок на мемах:** Мемы вставляются строго в чистом оригинальном виде без рамок, плашек и искусственных подложек.
4. **Зона динамических субтитров (`y=1480`–`y=1540`, `MarginV=420`):**
   - Нижняя 1/3 экрана (`y=1380`–`y=1920`) всегда остается свободной для субтитров и интерфейса платформ.
   - Крупный жирный шрифт (Arial / Montserrat, 48px).
   - **Акцентная плашка на слове:** Ключевые слова выделяются мягкой оранжевой плашкой с закруглениями синхронно со звуком речи.
   - **Безопасная зона снизу (`380px` до края экрана):** Субтитры расположены строго выше кнопки «Подписаться», аватарки канала, названия ролика и интерфейса YouTube Shorts / TikTok.

## 4. Синхронизация голоса и визуала (Scene-based Blocks & Mandatory Outro)
- Озвучка генерируется **по смысловым блокам** (Хук -> Расследование -> Схема 1 -> Схема 2 -> Фикс -> Финал/Outro).
- **ОБЯЗАТЕЛЬНАЯ финальная закрывашка подписки (Outro Motion Video):** Каждый ролик **ОБЯЗАТЕЛЬНО** заканчивается финальной анимированной закрывашкой на зеленом экране (`output/templates/outro_subscribe_motion.mp4`).
- **Правила рендера Outro:**
  - **Без перемонтажа и зацикливания:** Оутро **НЕ зацикливается** (`-stream_loop` запрещен), НЕ обрезается и НЕ меняется. Проигрывается **ровно 1 раз** со своей **родной аудиодорожкой**.
  - **Чистый хромакей без зеленых краев (No Green Fringe):** Применять FFmpeg фильтр `chromakey=0x00FF00:0.28:0.15` (или `colorkey=0x00FF00:0.28:0.15`), чтобы полностью срезать зеленый ореол и антиалиасинг с закругленных углов плашки.
  - **Обязательный сдвиг таймстампов (PTS Shift):** При наложении оутро видеопоток ОБЯЗАТЕЛЬНО сдвигается по времени на момент старта блока (`setpts=PTS-STARTPTS+start_t/TB`). Без сдвига FFmpeg вычитывает видео в первые 3 секунды ролика, и в блоке `outro` оутро виснет на статичном последнем кадре.
- **Точная привязка по таймингу:** Видеозакрывашка накладывается по центру экрана (`overlay=(W-w)/2:860`) **СТРОГО в момент старта финального речевого блока `outro`** (`start_t = block_timings["outro"]["start"]`).
- Тайминги визуальных карточек и мемов **автоматически привязываются к реальной длительности соответствующего речевого блока**. Это исключает любое отставание голоса от картинки.
- Эмбиент из бесплатной фонотеки YouTube `assets/music/ambient/` (No Copyright / Safe for monetization) стартует строго на блоке «Начинаем расследование».

## 5. Мемы, GIF, Видеомемы и SFX (Политика подбора и авторасчета таймингов)
- **🎭 Комплексный стандарт подбора и расстановки мемов (Meme Flow & Placement Standard):**
  1. **Пространственное разделение (Zero-Overlap Dynamic Area):**
     - *Зона геймплея (`y=200`–`y=774`):* Всегда чистая.
     - *Динамическая нижняя зона (`y=860`–`y=1400`):* Взаимно исключающие стейты:
       - **Стейт 1 (Карточки/Схемы активны на `y=780`):** Мемы **100% ЗАПРЕЩЕНЫ**.
       - **Стейт 2 (Схемы НЕ активны: Вводный оригинал 0–8s / Завязка / Хук):** Зона `y=860` активно заполняется мемами.
  2. **Временная структура и Правило непрерывного заполнения (Zero Void Rule):**
     - *Фаза 1: Вводный оригинал геймплея (0.0s – 8.0s):* Нижняя зона (`y=860`) **НЕ ДОЛЖНА ПУСТОВАТЬ**. Заполняется последовательной цепочкой из 2–3 ситуационных мемов (по 3–4 секунды каждый: Мем 1 `0.5s–4.0s`, Мем 2 `4.0s–7.8s`) с плавным переходом `fade=0.2s`.
     - *Фаза 2: Завязка и Хук диктора (8.0s – ~13.5s):* Выводится Мем 3 (`8.2s–13.0s`), отражающий эмоцию/вопрос диктора.
     - *Фаза 3: Разбор и карточки (~13.5s – ~32.0s):* Мемы отключены (активны 2D-схемы и карточки кода).
     - *Фаза 4: Outro (~32.0s – конец):* Выводится плашка `outro_subscribe_motion.mp4` на `y=860`.
  3. **Политика поисковых запросов Tenor (Plot-matched Queries):**
     - Запросы формируются strictly под фактуру игрового фейла (`door closes behind my face meme`, `talk behind closed door meme`, `ignore door between us`, `cant hear meme`, `squinting glasses meme`).
- **Автоматический поиск мемов через TenorMemeFetcher:**
  - GIF-мемы, реакции и стикеры подбираются через `TenorMemeFetcher` (`src/core/meme_fetcher.py`) по контекстным ключевым словам блоков и реакций.
  - ⛔ **СТРОЖАЙШИЙ ЗАПРЕТ НА БЕЗДУМНЫЙ ПЕРЕИСПОЛЬЗОВАНИЕ КЭШИРОВАННЫХ МЕМОВ (No Cached Meme Reuse):** Категорически запрещено использовать старые файлы мемов из прошлых выпусков или статичные дефолтные мемы (`cat open mouth`). Под каждый выпуск подбираются строго УНИКАЛЬНЫЕ контекстные ключевые слова.
- **Точный расчёт секунд появления мемов и SFX:**
  - *По событию геймплея:* Привязка мема и SFX к конкретной секунде действия (например $t = 3.2\text{s}$).
  - *По событиям дикторской речи (TTS Word Boundaries):* Расчёт `meme_start` по миллисекундам произнесения ключевых слов из таймстампов Edge-TTS.
  - *FFmpeg монтаж:* Оверлей мема включает `fade=t=in:st=meme_start:d=0.15` в границах `enable='between(t, meme_start, meme_end)'`, а звук подмешивается через `adelay=meme_start_ms|meme_start_ms`.
- **Запрет рамок и искусственных подложек на мемах:** Мемы вставляются строго в своем чистом оригинальном виде — **никаких рамок, обводок, рамочных плашек (`_framed`) или карточек**.
- **Запрет AI-генерации картинок (95% правило):** Генерация картинок нейросетью категорически запрещена в 95% случаев.
- **Запрет текстовых «карточек» вместо мемов:** Не заменять реальные мемы искусственными текстовыми плашками/диалогами.
- **Анимированные GIF-мемы:** Поддерживаются GIF-файлы через FFmpeg (`-ignore_loop 0 -i assets/memes/<name>.gif`) с масштабированием и плавным появлением (`fade`) в нижней половине экрана (`y=860`).
- **Мемные звуки (SFX):** Автоматический поиск и скачивание звуков из **MyInstants** (`https://www.myinstants.com`) через модуль `MyInstantsSFXFetcher` в `assets/sfx/`.
- **Видеомемы (Chroma Key / Green Screen):** Поддерживаются MP4 видеомемы на зеленом фоне (через FFmpeg фильтр `colorkey=0x00FF00`) и короткие видео-инсерты с их оригинальным звуком (`assets/memes/video/`).

## 6. Метаданные и финальная выписка (Post-production Report)
После рендера каждого ролика файлы `description.txt` и `metadata.json` ОБЯЗАТЕЛЬНО генерируются строго через базовый генератор `src/core/metadata_generator.py` (`MetadataGenerator.generate()`). Ручное/сокращенное формирование `description.txt` категорически запрещено. Файл должен содержать все 4 стандартных блока:
1. 📌 **ЗАГОЛОВОК ДЛЯ YOUTUBE SHORTS / TIKTOK** (с тегами `#shorts #игры`)
2. 📝 **ПОЛНОЕ ОПИСАНИЕ** (с описанием бага, игрой и хэштегами)
3. 💬 **ЗАКРЕПЛЕННЫЙ КОММЕНТАРИЙ (PINNED COMMENT)**
4. 🏷 **ТЕГИ (TAGS ДЛЯ YOUTUBE STUDIO)**

После рендера агент обязан предоставить краткую структурированную выписку:
- 🎮 **Игра и баг:** название и суть
- 📁 **Папка ролика:** `output/<id>/`
- ⏱ **Хронометраж:** общая длительность и тайминги сцен
- 🎭 **Использованные мемы:** какие мемы/видеомемы подобраны и почему
- 🔊 **Аудиодорожка:** выбранный эмбиент и звуковые эффекты
- 🔗 **Ссылка на файл:** кликабельная ссылка на итоговый `video.mp4`

## 7. Политика безопасности контента и стоп-слова (Safe Content & Anti-Shadowban Rules)
Алгоритмы модерации YouTube Shorts и TikTok (NLP/ASR) строго пессимизируют и режут показы роликов, содержащих триггерные слова в названиях, описаниях, тегах, озвучке/TTS, субтитрах и карточках.

### 🚫 Жесткий запрет (Stop-Words Blacklist):
- **Смерть / Трупы:** `труп`, `трупы`, `мертвец`, `мертвый`, `умер`, `погиб`, `смерть`, `смертоносный`, `смертельно` (EN: `corpse`, `dead body`, `dead`, `died`, `death`, `deadly`).
- **Убийства / Насилие:** `убийство`, `убийца`, `убил`, `убивает`, `убить`, `казнь`, `суицид`, `самоубийство`, `зарезал`, `застрелил`, `задушил` (EN: `kill`, `kills`, `killed`, `killing`, `murder`, `suicide`, `execute`, `stab`, `strangle`).
- **Кровь и увечья:** `кровь`, `кровавый`, `кишки`, `расчленение`, `мясо` (EN: `blood`, `bloody`, `gore`, `dismember`).
- **Оскорбления и мат:** Любая нецензурная брань, медицинские ругательства (`дебил`, `даун`, `псих`, `шизик`, `инвалид`).

### 🛡️ Безопасный словарь замен (Фолбеки / Геймдев & Мем-сленг):
- **Вместо «Труп»:** `трухляк`, `мякиш`, `афк`, `регдолл (ragdoll)`, `бот`, `моделька`, `NPC`, `объект` (EN: `ragdoll`, `NPC`, `bot`, `character model`, `prop`).
- **Вместо «Смерть / Погиб»:** `закончились хп`, `антижизнь`, `умолк`, `0 HP`, `деспавн`, `геймовер`, `откат на спавн`, `фатальный глитч` (EN: `0 HP`, `HP depleted`, `game over`, `respawn`, `despawned`, `deleted`, `vanished`).
- **Вместо «Убивает / Убил»:** `финишнул`, `обезхапэшил`, `кокнул`, `отправил на спавн`, `отправил в космос/стратосферу`, `дезинтегрировал`, `забаговал`, `снёс`, `ликвидировал`, `вырубил` (EN: `yeeted`, `sent to space / orbit`, `eliminated`, `knocked out`, `despawned`, `deleted`, `erased`).
- **Вместо «Кровь / Урон»:** `красные пиксели`, `кетчуп`, `визуальный эффект`, `эффект партиклов` (EN: `red pixels`, `ketchup`, `damage VFX`, `particle burst`).

> [!IMPORTANT]
> **Золотое правило:** В идеале вообще избегать этой терминологии. Сценарии, карточки и названия должны строиться вокруг **физики движка, математики, коллизий, векторов, NaN, багов и юмора**, а не темы смерти или урона.
