# GameBug Shorts Creator Skill

Руководство и алгоритм создания новых выпусков для автоматизированного канала про игровые баги.

## Пошаговый пайплайн производства (3-Step Production Pipeline):

### 1. Этап 1: Получение вводных, нарезка геймплея и разбор бага
- **Вход от пользователя:** Ссылка на видео (YouTube / локальный файл), таймкоды и описание бага.
- **Действия агента:**
  - Скачивание видео strictly на **диск E:** (`assets/downloads/` или `output/<id>/temp/`). Использование диска C запрещено.
  - Нарезка фрагмента геймплея (5–10 сек) для фонового зацикливания.
  - **Превью отрезка в MP4:** Агент генерирует черновой короткий **MP4-видеоролик** для наглядной проверки пользователем.
  - **Принцип простоты (KISS):** Объяснение первопричины бага формулировать простыми жизненными словами через 2–3 очевидных фактора (коллизия, деление на 0 / NaN, пропуск тика физики).
- **Контрольная точка 1:** Пользователь в чате подтверждает отрезок геймплея и суть бага.

### 2. Этап 2: Сценарий, раскадровка и подбор схем (2D / 3D)
- **Сценарий по блокам:** Хук ➔ Расследование ➔ Схема 1 ➔ Схема 2 ➔ Фикс ➔ Финал (хронометраж: 35–45 сек).
- **Выбор формата объяснения:**
  - 🧊 **3D WebGL анимация (Three.js):** Для физических столкновений, пробития стен, 3D Frustum камеры, Raycast лучей, пружин и векторов сил.
  - 📊 **2D Вертикальная схема ($1000 \times 1280\text{ px}$, Top-to-Bottom):** Для логики кода, шейдеров, буферов памяти.
- **Правила верстки карточек (Mobile-First & Zero Empty Space):**
  - *Минимум текста:* Сжатые емкие тезисы без лишней терминологии.
  - *Минимум пустого места:* Экран телефона маленький, поэтому свободное место отдается под максимальное увеличение шрифта ($28\text{--}34\text{px}$) и крупные элементы.
  - *Плотность информации:* 2–4 записи на схему, **в идеале ровно 2 ключевых блока** (Шаг 1 и Шаг 2) во всю ширину.
- **Подбор мемов:** Оригиналы из `assets/memes/` без рамок + звуки MyInstants (SFX).
- Публикация артефакта с превью сценария и карточек.
- **Контрольная точка 2:** Пользователь отсматривает сценарий, схемы и мемы.

### 3. Этап 3: Правки и финальная сборка (строго по команде)
- **Итерация правок:** Агент точечно правит текст, заменяет мемы или схемы по замечаниям пользователя.
- **ОБЯЗАТЕЛЬНОЕ согласование в чате:** Сборка запускается СТРОГО явным текстовым ответом пользователя в чате («ОК», «Собирай», «Монтируй»). Автоподтверждение среды (`auto-approval hook`) НЕ считать согласием!
- **Финальный продакшн:**
  - Озвучка Edge-TTS по смысловым блокам с автосинхронизацией длительности.
  - Динамические субтитры с оранжевой плашкой и безопасной зоной $380\text{ px}$ снизу.
  - Аппаратный рендер в FFmpeg (NVIDIA NVENC) — strictly на **диске E:** (`output/temp/`).
  - Генерация `description.txt` и `metadata.json`.
  - Структурированный финальный отчет со ссылкой на готовый `video.mp4`.


## Технические стандарты и модули:

### 1. Подготовка структуры вывода
Использовать `EpisodeOutputManager(episode_id)` для создания изолированной папки `output/<episode_id>/`:
- `voice/`
- `subtitles/`
- `visuals/`
- `frames/`
- `temp/`

### 2. Мультиязычность (RU / EN) и озвучка (Scene-based)
- **Выбор языка в сценарии:** Параметр `"lang": "ru"` (по умолчанию) или `"lang": "en"`.
- **Голоса Edge-TTS:**
  - `ru`: `ru-RU-DmitryNeural` (темп `+8%`)
  - `en`: `en-US-ChristopherNeural` или `en-US-GuyNeural` (темп `+5%`)
- **Смысловые блоки:** Озвучка генерируется по блокам (Хук -> Расследование -> Схема 1 -> Схема 2 -> Фикс -> Финал).
- Длительность каждого блока автоматически определяет длительность показа соответствующей схемы или карточки, исключая любой рассинхрон.

### 3. Мемы и Видеомемы (Политика подбора)
- **Запрет рамок и подложек на мемах:** Мемы вставляются строго в своем чистом оригинальном виде — **никаких рамок, искусственных рамочных плашек (`_framed`), обводок или карточек**. Только чистая картинка/GIF/видео без лишних наслоений.
- **Запрет AI-генерации картинок (95% правило):** Генерация картинок нейросетью категорически запрещена в 95% случаев (за исключением прямой просьбы пользователя).
- **Запрет текстовых «карточек» вместо мемов:** Не заменять реальные мемы искусственными текстовыми плашками. Мем должен быть настоящим (фото, скриншот, шаблон, видеовставка). Водяные знаки и неидеальное качество («мыло») допустимы.
- **Поиск оригиналов мемов:** Мемы берутся из готовой базы `assets/memes/`, скачиваются оригиналы из сети либо используются видеомемы (`assets/memes/video/`).
- **Запрос пользователю (Human-in-the-loop):** Если точный и подходящий мем не удалось найти в сети или ассетах, процесс сборки **приостанавливается**, и агент обращается к пользователю с подробным описанием: какая именно картинка/видео требуется под конкретную фразу сценария.
- **Мемные звуки (SFX):** Автоматический поиск и скачивание звуков с **MyInstants** через `MyInstantsSFXFetcher`.
- **Видеомемы (Chroma Key / Green Screen):** Обрабатываются через `VideoMemeOverlay` с вырезанием зеленого фона (`colorkey`).

### 4. Генерация визуала (Top-to-Bottom Vertical Diagrams, Motion UI & 3D Three.js)
- **Правило верхних 2/3 экрана (Top 2/3 Diagram Coverage):** Во время показа схемы объяснения схема занимает пространство с самого верха экрана вниз примерно на 2/3 высоты кадра (`y=80`–`y=1360`, размер $1000 \times 1280\text{ px}$). Это освобождает огромное пространство и делает схему четкой без приближения на смартфоне.
- **Строгий вертикальный флоу (Сверху вниз, НЕ слева направо):** Схемы категорически запрещено делить на узкие горизонтальные колонки. Элементы идут вертикальным стеком:
  - *Шапка:* Заголовок темы (`32–36px` Bold) + бейдж этапа (`20–22px` Monospace).
  - *Шаг 1 (Верхний блок, во всю ширину):* 3D-мир / Исходное состояние, крупные иконки (50px+), параметры (`24–26px`).
  - *Переходный коннектор (Стрелка вниз $\Downarrow$):* Крупная стрелка вниз с формулой/расчетом (`24–26px`).
  - *Шаг 2 (Нижний блок, во всю ширину):* Реакция движка / Screen Space / баг, визуальная область и плашка ошибки (`24–26px`).
  - *Итог (Футер):* Вывод в 1 строку (`22–24px`).
- **Интеграция 3D Three.js & WebGL (`src/core/three_renderer.py`):**
  - **Процедурная 3D-графика (100% автономно):** Для геймдев-багов агент процедурно генерирует 3D-примитивы (капсулы коллизий `CapsuleCollider`, лучи `Raycast`, 3D пирамиды видимости `Frustum Projection`, кости скелета, пружины физического солвера `Havok/PhysX`).
  - **Пользовательские 3D-модели (`.glb` / `.gltf`):** При необходимости точной геометрии персонажа/техники файлы помещаются в `assets/3d/` и загружаются через Three.js `GLTFLoader`.
  - **Детерминированный рендер в MP4 / PNG:** Кадры генерируются через `window.renderFrameAtTime(t)` в Headless Chrome WebGL и кодируются в видео через FFmpeg NVENC GPU.
- **Дизайн-система (Strict Minimal Dark & Mobile-First):**
  - *Графитовый стиль:* Фон `#14161a` / `#1c1f26`, цветная полоса слева (`border-left: 8px solid <color>`), без лишнего кислотного неона.
  - *Крупная мобильная типографика:* Заголовки `32–36px`, подзаголовки `26–28px`, основной текст `24–26px`, формулы/код `22–25px`.
- **Принцип «ПОЧЕМУ, а не ЧТО»:** Схема обязана наглядно объяснять техническую первопричину бага в движке (стриминг VRAM, State Machine null_ptr, Bind Pose 0°).
- **Карточка фикса в коде:** Простой юмористический псевдокод `[-] НЕПРАВИЛЬНО` vs `[+] ПРАВИЛЬНО` (или `[-] WRONG` vs `[+] FIXED`).

### 5. Сборка видео в FFmpeg (Strict Zero-Overlap Grid)
Экран 1080x1920 строго разделен на изолированные зоны:
1. **Зона геймплея (`y=200`–`y=774`, ширина 1020px):** Центрированный геймплей на размытом фоне в беспрерывном лупе в сценах геймплея.
2. **Зона схем и объяснений (`y=80`–`y=1360`, $1000 \times 1280\text{ px}$):** Во время объяснения бага схема раскрывается на верхние 2/3 экрана с вертикальным флоу сверху вниз.
3. **Зона мемов (`y=860`–`y=1400`, макс. высота 540px):** В сценах геймплея мемы располагаются в нижней половине, не перекрывая геймплей сверху (`y<860`) и субтитры снизу (`y>1400`).
4. **Зона субтитров (`y=1480`–`y=1540`, `MarginV=420`):** Нижняя 1/3 экрана (`y=1380`–`y=1920`) всегда свободна для динамических субтитров с оранжевой плашкой и безопасной зоны `380px` от низа под кнопки YouTube Shorts / TikTok.
- **Аппаратный рендер на GPU:** Всегда использовать аппаратный кодек видеокарты NVIDIA NVENC (`VIDEO_CODEC = "h264_nvenc"`, `VIDEO_PRESET = "p4"`, `VIDEO_CQ = "20"` из `config.settings`), исключая 100% нагрузку на CPU.
- **Музыка из фонотеки YouTube (No Copyright / Safe for monetization):**
  - Использовать фоновые эмбиенты исключительно из бесплатной библиотеки YouTube (`assets/music/ambient/`), защищенные от DMCA/страйков.
  - Громкость: Голос (1.0) + эмбиент (0.14) со старта расследования + контекстные SFX под мемы (0.30–0.35).

### 6. Метаданные и финальная выписка
- Автоматически генерировать через `MetadataGenerator` (`src/core/metadata_generator.py`) файлы:
  - `output/<id>/description.txt` (готовый текст описания с таймлайном, хэштегами и закрепленным комментарием)
  - `output/<id>/metadata.json` (структурированные данные для API публикации)
- После каждого ролика выводить отчет: игра, баг, язык (RU/EN), папка `output/<id>/`, таймлайн, список мемов с обоснованием, аудио и ссылка на `.mp4`.
