# Onter's inn Shorts Creator Skill

Руководство и алгоритм создания новых выпусков для автоматизированного канала про игровые баги.

## Пошаговый пайплайн производства (3-Step Production Pipeline):

### 1. Этап 1: Получение вводных, нарезка геймплея и разбор бага
- **Вход от пользователя:** Ссылка на видео (YouTube / локальный файл), таймкоды и **1 предложение с прямой фактурой сутевой причины бага**.
  - *Правило ввода фактуры:* Пользователь дает 1 четкое предложение про суть бага (например: *"Грузовик едет по ИИ-сплайну и на перекрестке моментально поворачивает на 90°, сшибая игрока"*). Агент берет этот факт за незыблемый базис.
- **Действия агента:**
  - Скачивание видео strictly на **диск E:** (`assets/downloads/` или `output/<id>/temp/`). Использование диска C запрещено.
  - Нарезка фрагмента геймплея (5–10 сек) для фонового зацикливания.
  - **Frame Sampling Check (Обязательный контроль среза):** Извлечение 3 кадров (`0-2s`, `середина`, `последние 2s`), проверка отсутствия обрезков прошлых видео из компиляций и черных экранов.
  - **Превью отрезка в MP4:** Черновой вертикальный клип для подтверждения пользователем.
- **Контрольная точка 1:** Пользователь в чате подтверждает отрезок геймплея и суть бага.

### 2. Этап 2: Сценарий, раскадровка и Компактные Умные Карточки — 3 ВАРИАНТА
- **Создание 3 различных вариантов выпуска (Variant 1, Variant 2, Variant 3):**
  - Сразу 3 разных варианта сценария с отличающейся подачей, юмором и акцентами.
  - Рендеринг в подпапки (`output/<id>/variant1/video.mp4`, `variant2/video.mp4`, `variant3/video.mp4`) и копирование основного в `output/<id>/video.mp4`.

- **📐 Стандарт позиционирования Карточек (`SmartCardGenerator` / Center Overlay):**
  - **Центральный контейнер под геймплеем (`y=780`–`y=1380`):** Категорически запрещено накладывать карточки и схемы на верхний видеопоток геймплея (`y=200`–`y=774`). Все 2D-схемы и карточки кода позиционируются в центрально-нижней зоне экрана (`y=780`, `overlay=(W-w)/2:780`), оставляя геймплей сверху на 100% открытым.
  - **Разделение на 2 простые карточки (Split 2-Card Flow):** Категорически запрещено перегружать 1 кадр кучей текста. Схема разбивается на **2 последовательные легкие карточки**:
    - *Карточка 1 (Step 1/2):* Исходное состояние и 3D-мир.
    - *Карточка 2 (Step 2/2):* Ошибка движка и сбой стейт-машины.
  - **💻 Стиль ОС Window IDE для карточек кода:** Карточки кода рендерятся в виде **окна редактора ОС** (кнопки управления `🔴🟡🟢`, имя файла `RigidBodySolver.cpp`, блоки `[-] WRONG` vs `[+] FIXED`).
  - **🚫 Строгий 100% запрет на эмодзи (Strict Emoji Ban):** Категорически запрещено использовать любые эмодзи-символы во всех текстовых строках схем и карточек. Использовать строго чистые текстовые маркеры `[-]`, `[+]`, `[!]`, `[INFO]`, `*`, `//`, `->`.

- **🗣️ СТРОЖАЙШИЙ ЗАПРЕТ НА АНГЛИЙСКИЙ ЯЗЫК В ОЗВУЧКЕ / TTS (Strict Russian / Transliteration Rule):**
  - Категорически запрещено оставлять любые английские слова, термины, имена классов или методы в речевых текстах дикторов (`text` блоков для Edge-TTS). Озвучка сильно искажает произношение и «рыгает» при вызове английских терминов на русском голосе.
  - Все технические термины и названия движков/классов должны быть переведены или **строго транслитерированы на кириллицу**:
    - *Вместо* `Creation Engine` -> пишем `Криэйшн Энджин`.
    - *Вместо* `DialogueManager` -> пишем `Диалог Менеджер`.
    - *Вместо* `DoorAutoCloseTimer` -> пишем `Дор Авто Клоуз Таймер`.
    - *Вместо* `OnTriggerExit` -> пишем `Он Триггер Экзит`.
    - *Вместо* `Vault 81` -> пишем `Волт 81`.
  - **🚫 Запрет избыточного усложнения терминологии (No Overcomplicated Tech Jargon / Clean Plain Language Rule):**
    - Категорически запрещено перегружать речь дикторов узким птичьим языком:
      - Вместо `сокет аттача` -> говорим `пустой объект` или `точка привязки` / `крепление`.
      - Вместо `хэнд проп` -> говорим просто `крепление руки`.
      - Вместо `скелетная анимация` -> просто `анимация`.
      - Вместо `блендшейп` -> `анимация` перелистывания.
      - Вместо `в коде аттача` -> `в коде крепления`.
      - Вместо `по нормали взгляда непися` -> `к нормальному направлению` или `по взгляду персонажа`.
    - Текст должен быть живым, лаконичным и понятным обычному зрителю в Shorts/Reels, без занудной наукообразности.

- **🎭 Комплексный стандарт подбора и расстановки мемов (Meme Flow & Placement Standard):**
  1. **Пространственное разделение (Zero-Overlap Dynamic Area):**
     - *Зона геймплея (`y=200`–`y=774`):* Всегда чистая, без наложений.
     - *Динамическая нижняя зона (`y=860`–`y=1400`):* Работает по правилу взаимного исключения стейтов:
       - **Стейт 1 (Карточки/Схемы активны на `y=780`):** Мемы **100% ЗАПРЕЩЕНЫ**. Экран кода/схемы должен оставаться чистым.
       - **Стейт 2 (Схемы НЕ активны: Вводный оригинал 0–8s / Завязка / Хук):** Зона `y=860` превращается в сцену мемов.
  2. **Временная структура и Правило непрерывного заполнения (Zero Void Rule):**
     - *Фаза 1: Вводный оригинал геймплея (0.0s – 8.0s):* Нижняя зона (`y=860`) **НЕ ДОЛЖНА ПУСТОВАТЬ**. Заполняется последовательной цепочкой из 2–3 ситуационных мемов (по 3–4 секунды каждый: Мем 1 `0.5s–4.0s`, Мем 2 `4.0s–7.8s`) с плавным переходом `fade=0.2s`.
     - *Фаза 2: Завязка и Хук диктора (8.0s – ~13.5s):* Выводится Мем 3 (`8.2s–13.0s`), отражающий эмоцию/вопрос Светланы.
     - *Фаза 3: Разбор и карточки (~13.5s – ~32.0s):* Мемы отключены (активны 2D-схемы и карточки кода).
     - *Фаза 4: Outro (~32.0s – конец):* Выводится плашка `outro_subscribe_motion.mp4` на `y=860`.
  3. **Политика поисковых запросов Tenor (Plot-matched Queries):**
     - Запросы формируются strictly под жизненную фактуру игрового фейла (`door closes behind my face meme`, `talk behind closed door meme`, `ignore door between us`, `cant hear meme`, `squinting glasses meme`).
     - Запрещено использовать абстрактные дефолтные мемы. Каждый выпуск должен содержать уникальные контекстные реакции.

### 3. Этап 3: Единый рендер через Ядро (`PipelineRunner`) и Авто-Валидация
- **Сборка strictly через `src/core/pipeline_runner.py`:**
  - **Запрет одноразовых скриптов:** Рендеринг выполняется строго вызовом центрального ядра `PipelineRunner(episode_id)`.
- **⛔ Strict No-Polling Rule:** При запуске асинхронных или командных задач рендера (`run_command` с `IsDaemon=false`), агенту КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО вызывать `manage_task(Action="status")` в цикле.
- **🔍 5-Point Mandatory Smoke Test & Screenshot Validation (Авто-Валидация):**
  1. *Decodability Test:* `ffprobe` декод-тест всех `.mp4` файлов.
  2. *Dual-Voice Assert:* Проверка наличия аудиофайлов Светланы и Дмитрия.
  3. *Center Card Overlay Assert:* Извлечение кадра во время показа карточки и визуальный контроль расположения строго по центру ниже геймплея (`y=780`), без перекрытия верхнего видео (`y=200`–`y=774`).
  4. *TTS Russian Text Assert:* Проверка отсутствия английских букв (A-Z, a-z) в блоках озвучки.
  5. *Metadata Format Assert:* Контроль 4 секций в `description.txt`.

## Технические стандарты и модули:

### 1. Подготовка структуры вывода
Использовать `EpisodeOutputManager(episode_id)` для создания изолированной папки `output/<episode_id>/`:
- `voice/`, `subtitles/`, `visuals/`, `frames/`, `temp/`

### 2. Сборка видео в FFmpeg (Strict Zero-Overlap Grid)
- Зона геймплея: `y=200`–`y=774` (scaled 16:9).
- Зона карточек/схем: `y=780`–`y=1380` ($1000 \times 600\text{ px}$, `overlay=(W-w)/2:780`).
- Зона мемов: `y=860`–`y=1400` (активна в 0–8s и во время хука).
- Зона субтитров: `y=1480`–`y=1540` (`MarginV=420`).
- Аппаратный NVENC (`h264_nvenc`).
- Фоновый эмбиент из YouTube Audio Library (громкость 0.12) + SFX (0.20).
